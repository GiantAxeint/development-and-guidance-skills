# 反面教材复盘：免费域名被误判为另一家 DDNS 服务商的域（2026-09）

> 说明：真实事故复盘。为保护当事人隐私，域名与个人细节已泛化，教学结构完整保留。

## 症状

用户为个人站点 `your-site.dpdns.org`（示例）排 CDN 问题，与 AI 多轮沟通仍一头雾水，AI 给的排查步骤在用户的控制台里根本找不到对应入口。

## 用户实际环境（事实）

- 域名注册于 **DigitalPlat FreeDomain**（digitalplat.org 一类免费二级域名平台，与 us.kg 同门）。
- DNS 托管于 **Cloudflare**（该平台的标准玩法即注册后接入 Cloudflare 托管）。
- 因此排查应发生在 **Cloudflare dashboard** 与 **该免费域名平台的面板**之间，与 dynu **毫无关系**。

## AI 的错误链条（逐条对应铁律）

| 错误 | 违反的铁律 |
|---|---|
| 看到域名形似「免费动态 DNS 域」，未询问用户环境，直接判定为 dynu（另一家免费 DDNS 服务商）的域名 | 第 2 条：环境事实先问不猜，禁止从名字/长相联想 |
| dynu 提供的免费后缀是 ddnsfree.com / freeddns.org / kozow.com 等，从不含该平台后缀——联想本身也是错的，属零查证的记忆模式匹配 | 第 1 条：涉及具体服务未先浏览查证 |
| 给出 dynu 面板的排查步骤，用户找不到入口后，AI 未回头质疑初始假设，而是复述/变换说法重试 | 第 3 条：排查前未对齐入口；及「喊不对即回查前提」的精神 |
| 全程未对不确定处标注「我推断的，可能不准」，语气与确定事实无异 | 总纲：区分确定与推断 |

## 正确流程（应当如何做）

1. 用户说「我域名在 Cloudflare 出问题」→ 第 2 条：**先问清**「这域名在哪注册？DNS 托管在哪个面板？你是要配 CDN 还是解析？」——若用户答不上，AI 自己查 whois / 浏览该免费域名平台官网确认归属。
2. 查证（第 1 条）：浏览 Cloudflare dashboard 相关文档 + 免费域名平台的面板说明，确认「免费域接 Cloudflare」是标准玩法。
3. 对齐入口（第 3 条）：确认用户当前在 Cloudflare 的哪个页面、卡在哪一步。
4. 一步一步推进（第 5 条），每步让用户回报结果。

## 通用教训

- 免费域名后缀众多且规则变动快（DigitalPlat、DuckDNS、eu.org、is-a.dev……），**记忆极易过时**，一律以实际浏览为准。
- 「看起来合理的错误」比「明显错误」危险得多：AI 若说「我不知道」，用户会去查；AI 自信地说错，用户就信了，白耗数轮。
